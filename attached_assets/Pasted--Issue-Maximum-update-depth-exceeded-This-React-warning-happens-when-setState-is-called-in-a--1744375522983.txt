⚠️ Issue: "Maximum update depth exceeded"
This React warning happens when setState() is called in a way that triggers a rerender → which re-triggers the useEffect that contains setState() → leading to an infinite loop.

🧠 Where This Likely Happens:
Inside your useEffect() that tracks userData and calls connect():

ts
Copy
Edit
useEffect(() => {
  if (userData && (userData as any)._websocketToken && !isConnected) {
    console.log('User data with WebSocket token available, attempting to connect');
    connect(); // <- causes socket state to change → triggers re-render → refires this effect
  }
}, [userData, isConnected, connect]);
If connect() sets setSocket() or setIsConnected(), and that causes userData to be refetched or updated, this becomes a loop.

✅ Fix: Add a Stable "hasAttemptedConnection" Ref
Use a useRef() to ensure the connect() logic runs only once per token — even if userData updates:

ts
Copy
Edit
const hasConnectedRef = useRef(false);

useEffect(() => {
  if (
    userData &&
    (userData as any)._websocketToken &&
    !isConnected &&
    !hasConnectedRef.current
  ) {
    console.log('User data with WebSocket token available, attempting to connect');
    hasConnectedRef.current = true;
    connect();
  }
}, [userData, isConnected, connect]);
💡 You can reset this flag in .onclose() if needed to allow reconnection after logout/relogin.

✅ Recap: Final WebSocket Sanity Checklist
✅ Item	Description
✓ One connection at a time	You check isConnecting and readyState before calling connect()
✓ Token check before connection	You confirm _websocketToken exists
✓ No infinite re-renders	Avoid connect() in useEffect loops without guards
✓ Backoff strategy for reconnection	You limit reconnect attempts after failures
✓ Server accepts valid tokens	You verified the token logic server-side
